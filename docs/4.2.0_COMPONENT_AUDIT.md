# Audit of the supplied 4.2.0 components

This audit reads six files from `origin/v3.0.0`, commit
`c5571573145775be1024477d39c9491531664147`. It describes their source behavior,
not an execution of that Windows installation. The branch name and the
embedded 4.2.0 paths are retained as provenance; the branch was not merged
over the working 4.2.1 bridges. Credential-bearing MCP configuration is not
included in this audit.

The central gap is that a submission receipt or favorable model prose was
being used where the requirements need an observed process, an accepted
artifact, and a fenced state transition. The six scripts below do not
collectively implement the specified scheduler, hardware-bound leases,
scatter/gather barrier, or immutable completion protocol.

## What carries forward

The four supplied specification files provide the acceptance contract. The
4.2.1 Codex/Claude adapters provide observable native CLI delegation. The new
`src/cochem_pipeline` modules supply the missing controller/store/Oracle and
execution coordination. Original source is retained in Git history; the old
scripts' labels such as “genuine,” “perfect,” or “4.2.0” are not accepted as
execution evidence.

The optional legacy Kanban server in the current checkout is also distinct
from the historical file examined above: its missing v3 queue import was
made lazy in 4.2.1 so it can report a submission error without preventing
server startup. It is not the new 4.2.2 controller frontend.

The [requirements matrix](REQUIREMENTS_4.2.2.md) records what is proven and
what still needs validation. The [deployment guide](PIPELINE_4.2.2.md)
describes the intended Windows runtime. The Agy native CLI invocation and
JSON result contract still require confirmation against the installed
Antigravity distribution; successful Gemini synthesis is not inferred from
the old prompt strings or from a configured model name.
