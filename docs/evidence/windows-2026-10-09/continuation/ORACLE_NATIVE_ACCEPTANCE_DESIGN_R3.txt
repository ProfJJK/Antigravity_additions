Relevant production contracts:
- S427-ORACLE-005: strictly more than 500 events per rolling second, asynchronous rogue-tree termination even IN_PROGRESS, physical cleanup before fencing/reaping, no unrelated collapse.
- Oracle.record uses real time.monotonic when now is omitted, trips at >500, schedules its callback through a separate executor, and performs no database operation in the event callback. A tripped task stops producing directives. Oracle.close waits for callback completion and surfaces callback failure.
- Runtime.SlotMonitor passes actual non-open/close filesystem events to Oracle.record. Runtime.trip invokes NativeRunner.terminate, waits for the execution-owner cleanup event, then calls Runtime.cancel and emits a recovery event. Its active dictionary and job-board fencing are separate from Oracle's component contract.
- NativeRunner._managed owns WindowsProcess.close and retains the active reference on cleanup failure; NativeRunner.terminate calls the process's native TerminateJobObject path.
- WindowsProcess.close waits on its owned process handle, polls the owned Job Object until ActiveProcesses==0, then closes process/job, unloads profile, closes token and releases the worker identity mutex. A PID existence check is not adequate cleanup evidence.
- Existing test_oracle.py uses fabricated event clocks with an ordinary direct child; test_windows_contract.py checks real worker descendant cleanup separately. Neither alone is this combined SYSTEM filesystem-storm acceptance.
