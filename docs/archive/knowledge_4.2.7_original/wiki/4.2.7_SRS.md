# CoChem 4.2.7 canonical pipeline SRS

**Specification ID:** `COCHEM-4.2.7`. **Owner decisions recorded:** 2026-10-06. **Target:** Windows 11, Windows Python, WSL2/Linux Docker, Antigravity 2.0 GUI, subscription-authenticated native CLIs. This is the clean normative specification for the pipeline, including its execution state machines. It replaces the withdrawn agentic seven-stage/Method Matrix prerequisite. It does not certify that every requirement has passed target-host acceptance.

Requirements use stable `S427-<chapter>-NNN` identifiers. **SHALL** is mandatory; **SHOULD** is a recommendation requiring an explicit disposition; improvement inserts are **nonbinding proposals for owner comment**, not implemented promises. “Implemented” means code exists; “verified” must name executed evidence and platform; “unverified” is not the same as “missing.” Code references are repository-relative and refer to the release containing this specification. Historical 4.2.6 measurements remain historical observations.

## Chapter 03: Durable job state machine

- **S427-STATE-001:** Controller transactions are the sole state authority. Each job has immutable request identity, workflow/parent relationship and kind; every executable attempt receives a fresh attempt ID, increasing fence, lease, worker/seat and captured route. Idempotent resubmission of the same ID/payload returns its existing workflow; different payload reuse is rejected. Workflow roots summarize children and do not consume an execution seat merely by existing.
- **S427-STATE-002:** Use SQLite WAL, `synchronous=NORMAL`, `busy_timeout=5000` and atomic `BEGIN IMMEDIATE` claims. Default lease is 1,800 seconds, supported maximum 3,600; heartbeat interval is at most five seconds and at most one-third of the lease. Do no inference, external retrieval or slow filesystem/subprocess operation inside a write transaction. Read-only monitors have no mutation authority.

| Persisted transition | Required prerequisite and atomic result |
| --- | --- |
| New → `PENDING` / `BLOCKED` | Validate captured request/policy; dependencies create a blocked node, otherwise pending. Root state and first nodes are committed together. |
| `PENDING` / `PENDING_RETRY` → `IN_PROGRESS` | Dependencies and eligibility time satisfied; admission and route reserved; unique live attempt/fence/lease recorded before launch. |
| `IN_PROGRESS` → `COMPLETED` | Current unexpired fence; matching native/controller receipt; exact immutable outputs and required physical evidence; release lease/route atomically. |
| `IN_PROGRESS` → `PENDING_RETRY` | Classified retryable failure; fence revoked, durable delay/budgets updated; physical cleanup must finish before a new launch. |
| Runnable/active → `BLOCKED` / `FAILED` | Record prerequisite, exhausted budget, terminal error or operator cancellation; revoke authority and prevent descendant dispatch. Cancellation persists `FAILED` plus `WORKFLOW_CANCELLED`; coding's aggregate projection is `CANCELLED`, not a separate SQL job status. |
| `BLOCKED` → `PENDING_RETRY` | Authenticated eligible resume with reason and restored prerequisite; preserve original failure/dispatch/cycle/deadline budgets. Terminal cancellation/exhaustion cannot be reset. |

- **S427-STATE-003:** Every transition leaving active execution clears both lease owner and expiry in the same transaction. Late zombie results, duplicate differing outputs, sibling identity claims and missing receipt bindings are rejected by controller checks and database constraints. Identical accepted completion replay is idempotent. Cleanup uncertainty retains the physical reservation/quarantine; it never frees a possibly live seat.
- **S427-STATE-004:** Availability waits are distinct from ordinary execution failures. Default ordinary failure budget is three; exhaustion leaves a terminal poison-pill hold. Dispatch, routing cycle/time and repair budgets are separate. Scheduler progress is not equivalent to completed work. Crash recovery reconciles launch, cleanup, output and integration journals without duplicate acceptance.
- **S427-STATE-005:** The coding execution contract SHALL be controller-owned, versioned and hashed (`cochem-planning/4.2.7`, specification `COCHEM-4.2.7`). Bind each stage to the permitted prior workflow state, phase, leaf, cycle, source snapshot and accepted predecessor job/receipt/evidence identities. Include `ExecutionContract.json` in the exact audited planning artifacts; recheck transition bindings before completion and final acceptance. A caller boolean cannot attest execution.
- **S427-STATE-006:** Coding aggregate labels such as `PLANNING`, `RESEARCHING`, `TESTING` and `READY_TO_INTEGRATE` are progress projections over real jobs. They neither replace the above statuses nor grant authority. A legacy, never-executed phantom-only `PLANNING_HOLD` may migrate through authenticated resume with a reason, original baseline retained and explicit migration evidence; real revision/no-progress/research holds remain enforced.

## Chapter 05: Coding execution

- **S427-CODE-001:** Snapshot a registered Git project and capture allowed source/test paths, exact baseline commit, image/test policy and governing execution contract. `CODE_PLAN` produces an SRS skeleton/chapters, requirements, reciprocal acceptance/test traceability, acyclic `graph.json`/`graph.mmd`, `FractureManifest.json` and batches of at most 20 leaves. Each SRS/chapter is at most 400 lines; each leaf has one implementation target and a planned 20–100-line context. Every requirement and criterion is covered.
- **S427-CODE-002:** `CODE_PLAN_REVIEW` independently audits every exact artifact/plan hash and requirement. Producer and reviewer cannot have the same actual provider/model pair. Only `PASS` enters implementation. `REVISE`/`FAIL` retain actionable artifact-bound findings, exact producer receipt identity and immutable revision history; bounded smart revisions must make relevant progress. No-progress/exhausted revision budgets create a real hold.

## Chapter 07: Shared concurrency and hardware

Resource policy may lower capacity to zero; no route, retry, warm pool or resume raises it above four.
- **S427-HOST-002:** Collect actual CPU utilization/count/temperature, available RAM, Windows commit headroom, GPU utilization/VRAM/temperature, required-volume free space and disk throughput/IOPS. Missing required sensors cause a visible admission hold, never a zero-valued healthy reading. CPU-only/sensor exceptions require an explicitly configured host profile and cannot claim the omitted guarantee.
- **S427-HOST-003:** Default CPU/RAM admission bands are four seats below 30% CPU with >16 GiB free, three below 50%/>8 GiB, two below 70%/>4 GiB, one below 85%/>2 GiB, otherwise zero, further bounded by measured memory/commit reserves and physical CPUs. Reserve at least the larger permitted native/container memory cap per seat; do not subtract already measured RAM-disk allocation twice.
- **S427-HOST-004:** Default protections: CPU pause/critical 95%/99%; CPU temperature 85/95°C; GPU temperature 85/92°C; VRAM throttle above 80%, pause at 90%, sustained critical at 98%; free RAM reserve/critical 1,024/256 MiB; free commit 6,144/512 MiB; disk reserve/critical 512/128 MiB; disk I/O pause above 120 MiB/s or 4,000 IOPS. These are configurable protective defaults, not invented historic host measurements. Immediate thermal/critical reserve trips override state gating; sustained pressure confirms after five seconds. Recovery requires ten healthy seconds and three samples, increasing by one seat.
- **S427-HOST-005:** Before resuming a native child, verify its Windows Job Object limits: aggregate 2,048 MiB memory, 20% CPU rate and 16 processes by default, kill-on-close, E-core affinity and BelowNormal priority. Resolve E cores from actual topology rather than assume `0x00FF0000`. Warden itself uses verified E-core/BelowNormal scheduling. Set no-window/new-process-group flags and separate 100–500 ms launch/poll jitter. Node old-space is at most 512 MiB; this is not a total process/heap cap and does not govern Rust/Bun.
- **S427-HOST-006:** Warden monitors its own measured RSS/CPU; violation of 50 MiB/5% pauses admission. Required native acceptance includes <15% actual desktop-heap allocation use and a 48-hour handle/resource stability run. USER/GDI counts cannot substitute for desktop-heap used/capacity evidence. ## Chapter 08: Oracle context and circuit breaker

- **S427-ORACLE-001:** The SYSTEM-tier Warden observes filesystem/database events and applies a 500 ms debounce before watermark checking or new rule generation. Consolidate events; do not inject during an incomplete debounce interval or feed injected hints back into an infinite loop.
- **S427-ORACLE-002:** Use Aho-Corasick faceted retrieval with overlapping matches and knapsack context selection. Reserve a configured baseline percentage for non-evictable core rules. Count the complete encoded/XML-wrapped context against its budget and escape `<oracle_directive>` content. Insufficient core capacity is a failure, never silent eviction.
- **S427-ORACLE-003:** Store cryptographic watermarks and ordered delivery generations in private out-of-band SQLite inaccessible to workers. Drain→set context→ack is serialized; acknowledge the exact generation. Repeated A→B→A must deliver the second A, while stale acknowledgments cannot erase newer context. Preserve delivery state through restart.
- **S427-ORACLE-004:** Deliver transient context via SQLite-controlled payload or protected local named pipe/inherited read handle, never `.warden_hints.md` or worker-writable prompt files. Bound delivery/backpressure and cancel cleanly. Verify workspace Defender exclusions and Search Indexer non-indexed attributes; preserve persistent authentication and protected logs.
- **S427-ORACLE-005:** Strictly more than 500 events per rolling second trips the velocity breaker immediately even during `IN_PROGRESS`, bypassing normal state gates.
