
### 3.3 Upgraded `task_work_loop_v2.py`

#### 3.3.1 Responsibilities and non-responsibilities

The loop **owns**: polling, concurrency, lease renewal, dispatch to the gateway, evidence
capture, audit invocation, pivot invocation, telemetry, pause handling, graceful shutdown,
boot recovery.

The loop **does not own**: model selection (the gateway's `QuotaFallbackRouter` does),
audit judgement (`audit_layer` + `cochem-audit` do), state legality (the queue manager does).
v1's loop conflated all of these into one 390-line file; the separation is what makes each
piece testable.

#### 3.3.2 Configuration

| Env var | Default | Rationale |
|---|---|---|
| `V2_MAX_CONCURRENCY` | `3` | Each slot may spawn a `claude.exe` on the host via the gateway; 3 concurrent Fable-5.1 CLI sessions is the measured ceiling before host RAM pressure on 32 GB. Hard cap 8, enforced in code. |
| `V2_POLL_INTERVAL_BUSY_MS` | `2000` | Work found last cycle → poll fast. |
| `V2_POLL_INTERVAL_IDLE_MS` | `15000` | Idle backoff ceiling, matching v1's idle cadence. |
| `V2_LEASE_SECONDS` | `1800` | 30 min. A Fable-5.1 refactor task legitimately runs 20+ min; the lease must exceed p99 task duration or healthy work gets reclaimed mid-flight. |
| `V2_HEARTBEAT_SECONDS` | `30` | Lease renewal cadence; 60× margin against the 1800 s lease. |
| `V2_MAX_AUDIT_CYCLES` | `3` | v1 used 10, which burns ~10 Fable calls on a task the auditor already failed twice. A task that fails audit 3× needs a different plan, not another revision — so cycle 4 routes to pivot. |
| `V2_MAX_PIVOT_CYCLES` | `3` | Matches v1's `MAX_PIVOT_CYCLES`; now persisted per-task in the DB. |
| `V2_AUDIT_PASS_THRESHOLD` | `85` | See §3.4.3. |
| `V2_QUEUE_DEPTH_LIMIT` | `500` | Backpressure at submit. |
| `V2_TASK_TIMEOUT_SEC` | `3600` | Matches `llm_router`'s existing 3600 s subprocess timeout. |
| `V2_QUOTA_PAUSE_SEC` | `900` | 15 min. v1 slept 300 s inside the task path, blocking the whole (serial) pipeline; v2 pauses the *queue* and releases leases. |

#### 3.3.3 Main loop structure

```python
"""task_work_loop_v2.py — async Kanban daemon, DB-queue driven.

Differences from v1 .scripts/task_work_loop.py that matter:
  * Polls kanban_tasks via KanbanQueueManager.claim_task(), not glob() of a prompts dir.
  * N concurrent workers behind an asyncio.Semaphore; a failing task cannot block others
    (v1 used `break`, giving head-of-line blocking on a serial executor).
  * No work_loop_state.json. Completion lives in the DB and is never deleted.
  * Boot-time recover_orphans() reclaims leases from the previous process lifetime.
  * Quota pause is a durable queue state, not a module-level bool in another module.
  * Evidence for audit is read from disk by THIS process, with pre/post hashes.
  * Every transition writes kanban_telemetry + kanban_task_events.
"""

import asyncio, os, signal, socket, time, uuid


class WorkLoopV2:
    def __init__(self, cfg: Config) -> None:
        self.cfg = cfg
        self.worker_id = f"{socket.gethostname()}:{os.getpid()}:{uuid.uuid4().hex[:8]}"
        self.q = KanbanQueueManager(cfg.db_path, worker_id=self.worker_id,
                                    queue_version=cfg.queue_version,
                                    lease_seconds=cfg.lease_seconds)
        self.gateway = LLMGatewayClient(cfg.gateway_url, cfg.gateway_token)
        self.auditor = AuditLayer(self.q, self.gateway, cfg)
        self.pivot = PivotOrchestrator(self.q, self.gateway, cfg)
        self.sem = asyncio.Semaphore(min(cfg.max_concurrency, 8))
        self._in_flight: dict[str, asyncio.Task] = {}
        self._shutdown = asyncio.Event()
        self._draining = False

    async def run(self) -> None:
        self.q.register_worker(max_concurrency=self.cfg.max_concurrency,
                               container_id=_read_container_id())
        reclaimed = self.q.recover_orphans()          # BOOT RECOVERY — v1 bug #8
        log.info("boot recovery reclaimed %d orphaned task(s): %s", len(reclaimed), reclaimed)

        self._install_signal_handlers()
        async with asyncio.TaskGroup() as tg:
            tg.create_task(self._serve_health())      # :8790
            tg.create_task(self._heartbeat_loop())    # worker + per-task lease renewal
            tg.create_task(self._sweeper_loop())      # expired leases + WAL checkpoint
            tg.create_task(self._dispatch_loop())     # the poller

    async def _dispatch_loop(self) -> None:
        while not self._shutdown.is_set():
            paused, until, reason = self.q.pause_status()
            if paused:
                if time.time() >= until:
                    self.q.resume_pipeline()
                else:
                    await self._sleep_or_shutdown(min(30.0, until - time.time()))
                    continue

            if self._draining or len(self._in_flight) >= self.cfg.max_concurrency:
                await self._sleep_or_shutdown(1.0)
                continue

            claimed = await asyncio.to_thread(self.q.claim_task)
            if claimed is None:
                await self._sleep_or_shutdown(self.cfg.poll_idle_ms / 1000)
                continue

            t = asyncio.create_task(self._run_task(claimed), name=f"task:{claimed.task_id}")
            self._in_flight[claimed.task_id] = t
            t.add_done_callback(lambda _t, tid=claimed.task_id: self._in_flight.pop(tid, None))
            await self._sleep_or_shutdown(self.cfg.poll_busy_ms / 1000)
```

#### 3.3.4 Per-task pipeline

```python
    async def _run_task(self, task: ClaimedTask) -> None:
        async with self.sem:
            lock = task.worker_lock_id
            try:
                self.q.set_state(task.task_id, lock, TaskState.EXECUTING,
                                 event_type="EXEC_STARTED")

                # Pre-execution workspace fingerprint. Without this, "the agent claims it
                # wrote file X" is unfalsifiable — which is exactly v1's audit defect.
                pre = await asyncio.to_thread(snapshot_workspace, task, self.cfg.workspace)

                t0 = time.monotonic()
                try:
                    result = await self.gateway.generate(
                        agent_name=task.agent_name,
                        prompt=_wrap_execution_prompt(task),
                        timeout=self.cfg.task_timeout_sec,
                    )
                except QuotaExhausted as exc:
                    # ALL cloud tiers gone. Durable pause; release the lease so another
                    # worker (or this one post-resume) can take it. v1 slept 300s inline.
                    self.q.set_state(task.task_id, lock, TaskState.PAUSED_QUOTA,
                                     detail={"reason": str(exc)})
                    self.q.pause_pipeline(reason=str(exc), seconds=self.cfg.quota_pause_sec)
                    self.q.requeue_task(task.task_id, lock, reason="quota pause",
                                        delay_seconds=self.cfg.quota_pause_sec)
                    return
                except GatewayTimeout as exc:
                    self.q.fail_task(task.task_id, lock, error=str(exc),
                                     error_class="timeout", retryable=True)
                    return
                exec_ms = int((time.monotonic() - t0) * 1000)

                if not (result.content or "").strip():
                    self.q.fail_task(task.task_id, lock, error="empty LLM response",
                                     error_class="empty_response", retryable=True)
                    return

                post = await asyncio.to_thread(snapshot_workspace, task, self.cfg.workspace)
                bundle = build_evidence_bundle(pre, post, result, task, self.cfg.workspace)

                self.q.set_state(task.task_id, lock, TaskState.AWAITING_AUDIT,
                                 detail={"exec_ms": exec_ms,
                                         "provider": result.provider, "model": result.model,
                                         "evidence_files": bundle.file_count,
                                         "evidence_bytes": bundle.total_bytes})

                await self._audit_cycle(task, lock, result, bundle)

            except TaskNotClaimed:
                # Lease was stolen mid-flight (this worker was presumed dead). Abandon
                # silently WITHOUT writing results — the split-brain guard. Another worker
                # owns the task now, and two writers would corrupt its state.
                log.warning("lease lost for %s; abandoning without write", task.task_id)
            except Exception as exc:
                self.q.fail_task(task.task_id, lock, error=repr(exc),
                                 error_class=type(exc).__name__, retryable=True)
                log.exception("unhandled error on %s", task.task_id)

    async def _audit_cycle(self, task, lock, result, bundle) -> None:
        cycles = task.audit_cycles
        while cycles < self.cfg.max_audit_cycles:
            cycles += 1
            self.q.set_state(task.task_id, lock, TaskState.AUDITING,
                             event_type="AUDIT_STARTED", detail={"cycle": cycles})
            verdict = await self.auditor.audit(task, result, bundle, cycle=cycles)

            if verdict.kind is Verdict.SPOOFING:
                self.q.quarantine_task(task.task_id, lock, reason=verdict.critique,
                                       evidence=verdict.as_dict())
                await self.auditor.escalate_council(task, verdict)
                return

            if verdict.kind is Verdict.PASS:
                self.q.complete_task(task.task_id, lock, result_uri=verdict.result_uri,
                                     audit_id=verdict.audit_id,
                                     evidence_sha256=bundle.sha256)
                return

            # FAIL or INDETERMINATE -> revision
            self.q.set_state(task.task_id, lock, TaskState.REVISION,
                             event_type="REVISION_DISPATCHED",
                             detail={"cycle": cycles, "critique": verdict.critique[:4000]})
            pre = await asyncio.to_thread(snapshot_workspace, task, self.cfg.workspace)
            self.q.set_state(task.task_id, lock, TaskState.EXECUTING)
            result = await self.gateway.generate(
                agent_name=task.agent_name,
                prompt=_wrap_revision_prompt(task, verdict),
                timeout=self.cfg.task_timeout_sec)
            post = await asyncio.to_thread(snapshot_workspace, task, self.cfg.workspace)
            bundle = build_evidence_bundle(pre, post, result, task, self.cfg.workspace)
            self.q.set_state(task.task_id, lock, TaskState.AWAITING_AUDIT)

        # Audit cycles exhausted -> pivot council
        self.q.set_state(task.task_id, lock, TaskState.PIVOT, event_type="PIVOT_STARTED")
        await self.pivot.run(task, lock, failure_trace=self.auditor.trace_for(task.task_id))
```

#### 3.3.5 Evidence capture — `snapshot_workspace` / `build_evidence_bundle`

This is the mechanism that repairs the fail-open audit. It is orchestrator-side and does not
trust the agent's self-report.

```python
@dataclass(frozen=True, slots=True)
class WorkspaceSnapshot:
    root: str
    files: dict[str, tuple[int, float, str]]   # relpath -> (size, mtime, sha256)
    taken_at: float
    truncated: bool                            # True if the scan hit MAX_SCAN_FILES

MAX_SCAN_FILES = 20_000
MAX_FILE_BYTES = 512 * 1024          # per-file read cap for hashing
SKIP_DIRS = {".git", "__pycache__", ".venv", "node_modules", ".pytest_cache", ".mypy_cache"}
SKIP_SUFFIXES = {".pyc", ".pyo", ".log", ".tmp", ".lock", ".db-wal", ".db-shm"}


def snapshot_workspace(task: ClaimedTask, workspace_root: str) -> WorkspaceSnapshot:
    """Hash every candidate file under the task's scoped workspace subtree.

    Scope = the narrowest of: the parent directory of task.file_path, or workspace_root.
    Narrow scoping is what keeps this cheap — a full-tree hash of D:\\__CoChem would take
    minutes, a scoped subtree takes milliseconds.
    """


@dataclass(frozen=True, slots=True)
class EvidenceBundle:
    created: list[str]
    modified: list[str]
    deleted: list[str]
    contents: dict[str, str]        # relpath -> text, each truncated to EVIDENCE_FILE_CHARS
    file_count: int
    total_bytes: int
    sha256: str                     # hash over the sorted (path, post-hash) pairs
    claimed_but_absent: list[str]   # agent said it wrote these; they do not exist
    unclaimed_changes: list[str]    # changed on disk but not claimed (scope creep/collateral)
    git_diffstat: str | None

EVIDENCE_FILE_CHARS = 24_000
EVIDENCE_TOTAL_CHARS = 180_000      # keeps the audit prompt inside a safe context budget


def build_evidence_bundle(pre, post, result, task, workspace_root) -> EvidenceBundle:
    """Diff two snapshots; read the actual bytes of whatever changed.

    Fixes four distinct v1 defects:
      1. v1 derived the file list from json.loads(exec_text) where exec_text was PROSE, so
         the list was always [] and the auditor received an empty string. Here the list
         comes from the pre/post disk diff, which the agent cannot influence.
      2. v1 used `break` when a claimed file was missing, truncating evidence for every
         later file. Here a missing claimed file is recorded in claimed_but_absent and the
         scan continues — a missing claimed file is the single strongest spoofing signal
         and must never be allowed to silently shorten the bundle.
      3. v1 capped at 20 files with no byte budget, so 20 large files could blow the
         context. Here per-file and total character budgets are enforced, with an explicit
         '[TRUNCATED: N more bytes]' marker so the auditor knows its view is partial.
      4. v1 had no notion of unclaimed changes. Files modified but not claimed are
         surfaced, because collateral edits outside the task's scope are a finding.

    ORCHESTRATOR-SIDE HARD FAIL: if `created` and `modified` are both empty for a task whose
    workflow_type is in MUTATING_WORKFLOWS, the loop does not consult the auditor at all —
    it records verdict FAIL with error_class='no_physical_change' and evidence_files=0.
    An auditor must never be asked to rule on zero evidence, because an LLM shown a
    confident summary and nothing that contradicts it returns PASS.
    """

MUTATING_WORKFLOWS = {"coding", "improvement", "srs", "syllabus", "questions",
                      "manual_assembly", "v2_build", "v2_test"}
```

#### 3.3.6 Graceful shutdown and drain

`stop_grace_period: 120s` in compose gives the sequence below room to finish.

```python
    def _install_signal_handlers(self) -> None:
        loop = asyncio.get_running_loop()
        for sig in (signal.SIGTERM, signal.SIGINT):
            loop.add_signal_handler(sig, lambda s=sig: asyncio.create_task(self._drain(s)))

    async def _drain(self, sig) -> None:
        """SIGTERM -> stop claiming, let in-flight finish, then release cleanly.

        v1 had no handler at all: a docker stop or Ctrl-C killed it mid-task, leaving the
        prompt file on disk and the completion unrecorded — the exact shape of v1 bug #8.
        """
        if self._draining:
            return
        self._draining = True
        self.q.deregister_worker(status="draining")
        log.info("drain: signal=%s in_flight=%d", sig.name, len(self._in_flight))

        deadline = time.time() + 100          # < stop_grace_period, leaves 20s of margin
        while self._in_flight and time.time() < deadline:
            await asyncio.sleep(1)
            # leases keep being renewed by _heartbeat_loop throughout the drain

        # Anything still running at the deadline is released back to QUEUED, not abandoned.
        for task_id in list(self._in_flight):
            self.q.requeue_task(task_id, None, reason="worker drained before completion")
        self.q.checkpoint_wal(truncate=True)
        self.q.deregister_worker(status="stopped")
        self._shutdown.set()
```

#### 3.3.7 Telemetry writing

`kanban_telemetry` has `NOT NULL` on `execution_time_ms`, `cpu_percent`, `vram_used_mb`,
`status_verdict`, `worker_id`, `state_from` and `state_to`, so the writer must supply all
seven on every row. v1's loop wrote none.

```python
"""telemetry_writer.py — one kanban_telemetry row per state transition."""

def write_telemetry(conn, *, task_id: str, worker_id: str,
                    state_from: int, state_to: int, execution_time_ms: int,
                    status_verdict: str, agent_name: str | None = None,
                    provider: str | None = None, model: str | None = None,
                    input_tokens: int | None = None, output_tokens: int | None = None,
                    error_class: str | None = None, cost_usd: float = 0.0) -> None:
    """Insert into kanban_telemetry inside the CALLER's transaction.

    cpu_percent: psutil.Process().cpu_percent() for this worker process.
    vram_used_mb: from `nvidia-smi --query-gpu=memory.used --format=csv,noheader,nounits`,
        cached for 5 s, defaulting to 0 when unavailable. The container has no GPU under
        ADR-003, so 0 is the normal value there; the host watchdog records the real figure.
    Both columns are NOT NULL in the existing schema and must never be passed None.

    status_verdict vocabulary (extends the existing rows' 'DONE'):
        DONE | FAIL | SPOOFING | PAUSED | REQUEUED | CLAIMED | AUDIT_PASS | AUDIT_FAIL |
        PIVOT | QUARANTINE | RECOVERED
    """
```

A telemetry row is written for **every** transition, in the same transaction as the status
change, so telemetry can never disagree with task state. `kanban_task_events` carries the
unbounded structured detail; `kanban_telemetry` carries the fixed-width metrics that existing
consumers already read.

### 3.4 Asymmetric Audit Layer — `audit_layer.py`

#### 3.4.1 Interception point

A task moves `AWAITING_AUDIT(3) → AUDITING(4) → DONE(7)`. There is no path from `EXECUTING(2)`
to `DONE(7)` in `LEGAL_TRANSITIONS`, and `complete_task()` re-validates the
`kanban_audit_results` row inside its own transaction. Audit is therefore not a policy the loop
is trusted to honour — it is a precondition the queue enforces. A future code path that forgot
to audit would raise `IllegalTransition`, not silently close the task.

#### 3.4.2 Asymmetry rules

The verifying triple must differ from the producing triple. The check runs against the
**actual** provider/model the gateway reports, not the registry's nominal primary — because
`QuotaFallbackRouter` may have degraded the executor to Gemini, which could then collide with a
nominally-Gemini auditor.

```python
AUDIT_PAIRS: dict[str, list[str]] = {
    "cochem-coder":           ["cochem-audit", "cochem-peer-reviewer"],
    "cochem-scribe":          ["cochem-audit", "cochem-peer-reviewer"],
    "cochem-tester":          ["cochem-audit"],
    "cochem-author":          ["cochem-academic-editor", "cochem-peer-reviewer"],
    "cochem-improve":         ["cochem-audit"],
    "cochem-audit":           ["cochem-peer-reviewer"],   # auditing the auditor
    "cochem-peer-reviewer":   ["cochem-audit"],
    "pivot-planner":          ["cochem-audit"],
}
DEFAULT_AUDITOR = "cochem-audit"


def enforce_asymmetry(exec_triple, audit_triple) -> tuple[bool, str]:
    """Returns (ok, reason). Three independent rules, all must hold:

      R1 agent inequality:    audit_agent != exec_agent
      R2 model inequality:    (audit_provider, audit_model) != (exec_provider, exec_model)
      R3 session inequality:  the audit must be a NEW gateway request with no shared
                              conversation state. Guaranteed by the gateway being stateless
                              (each /generate is an independent subprocess) and asserted
                              here via distinct request_id values.

    R1 alone is insufficient. Two agent names can resolve to the same (provider, model):
    in the CURRENT MODEL_REGISTRY, cochem-coder and cochem-audit are BOTH
    claude-subscription/claude-fable-5-1. Without R2, the 'asymmetric' audit is the same
    model grading its own homework behind a different system prompt. This is the concrete
    reason the layer cannot rely on agent names.
    """
```

**Consequence for the existing registry, which must be handled at build time.** Because
`cochem-coder` and `cochem-audit` share `claude-subscription/claude-fable-5-1`, R2 fails on the
happy path. The audit layer resolves this by requesting an explicit model override for the
audit call, in this preference order:

1. A different provider at comparable capability: `gemini/gemini-3.1-pro-preview`.
2. If Gemini is quota-disabled: `claude-subscription/claude-sonnet-4-5` — a different model on
   the same provider, which satisfies R2.
3. If only one model remains reachable: the audit is recorded with `asymmetry_ok = 0`, the task
   goes to `blocked` with `audit_status='rejected_symmetry'`, and **it is not marked done**. A
   single-model pipeline cannot produce a valid verification, and quietly accepting one is
   exactly the anti-spoofing violation this layer exists to prevent.

The gateway's `force_model` field exists for this purpose (§3.7).

The response is parsed into a pydantic model. A parse failure is retried once with a
`"Return ONLY the JSON object."` reminder; a second failure is recorded as `INDETERMINATE` with
`score=0`, which routes to revision — **never** to `PASS`. v1 treated a malformed auditor
response as `FAIL`, which was right in spirit; v2 makes the fail-closed default structural.

```python
class AuditFinding(BaseModel):
    severity: Literal["critical", "major", "minor"]
    file: str
    line: int | None = None
    issue: str
    required_fix: str

class AuditVerdict(BaseModel):
    verdict: Literal["PASS", "FAIL", "SPOOFING_DETECTED", "INDETERMINATE"]
    score: int = Field(ge=0, le=100)
    critique: str
    findings: list[AuditFinding] = []
    evidence_sufficient: bool = True

    @model_validator(mode="after")
    def _coherence(self) -> "AuditVerdict":
        # An auditor cannot return PASS while reporting a critical finding, or PASS below
        # threshold. Incoherent verdicts are downgraded rather than trusted.
        if self.verdict == "PASS" and (
            self.score < 85 or any(f.severity == "critical" for f in self.findings)
        ):
            object.__setattr__(self, "verdict", "FAIL")
        return self
```

#### 3.4.4 Pass/fail thresholds and escalation

| Condition | Action |
|---|---|
| Orchestrator finds `evidence_files == 0` on a mutating workflow | `FAIL`, `error_class='no_physical_change'`. The auditor is **not** invoked. |
| `asymmetry_ok == 0` and no alternative model reachable | `blocked`, `audit_status='rejected_symmetry'`, operator alert. Never `done`. |
| `verdict == PASS`, `score >= 85`, no critical findings, `asymmetry_ok == 1` | `complete_task()` → `done`. |
| `verdict == FAIL` / `INDETERMINATE`, cycles remain | Revision dispatched with the critique; `audit_cycles += 1`. |
| Audit cycles exhausted (3) | → `PIVOT(6)`, pivot council. |
| `verdict == SPOOFING_DETECTED` | → `QUARANTINE(9)` **immediately**, no revision. Full evidence persisted. Council escalation. |
| Pivot cycles exhausted (3) | → `FAILED(8)`, `HARD_ABORT: PHYSICS WALL`, operator alert. |

Escalation on spoofing invokes the `0rchestrator` agent — preserving v1's `run_agent_council`
intent — but the outcome is now written to `kanban_task_events` rather than only logged, and the
task stays quarantined regardless of what the council concludes. Quarantine release is a
deliberate operator action (`release_quarantine` with a written justification), never automatic.

#### 3.5.3 Authentication

```python
"""Bearer-token auth. v1 had none: any local process could trigger unbounded LLM spend."""

_TOKEN = os.environ.get("V2_MCP_TOKEN", "")
if len(_TOKEN) < 32:
    raise SystemExit("V2_MCP_TOKEN must be >= 32 chars. Refusing to start unauthenticated.")

def _authorize(authorization: str | None) -> None:
    if not authorization or not authorization.startswith("Bearer "):
        raise McpError(code=401, message="missing bearer token")
    # compare_digest is constant-time, so a wrong token cannot be discovered byte-by-byte
    # through response-timing differences.
    if not hmac.compare_digest(authorization[7:], _TOKEN):
        _audit_auth_failure(_peer())
        raise McpError(code=403, message="invalid token")
```

Additional controls: the HTTP listener binds `0.0.0.0` **inside the container** but is published
only to `127.0.0.1:8791`, so it is unreachable off-host. Failed auth attempts are written to
`kanban_task_events` with `event_type='AUTH_FAILURE'`; 10 failures from one peer inside 60 s
block that peer for 15 minutes. `healthz` is the only unauthenticated route, and only when the
peer address is loopback.

#### 3.5.4 Rate limiting

Token bucket per `(peer, tool)`, plus a global bucket. Mutating tools are limited far more
tightly than reads, because each mutation can cost a Fable-5.1 call.

```python
RATE_LIMITS: dict[str, tuple[int, float]] = {      # (burst, refill per second)
    "submit_task":         (10,  10 / 60),         # 10 burst, 10/min sustained
    "submit_task_batch":   (2,    2 / 60),         # batches are large; keep them rare
    "retry_task":          (10,  10 / 60),
    "release_quarantine":  (3,    3 / 3600),       # 3/hour — deliberately painful
    "pause_pipeline":      (5,    5 / 60),
    "trigger_pivot":       (5,    5 / 60),
    "_default_read":       (60,  60 / 60),
    "_global":             (120, 120 / 60),
}
```

Exceeding a bucket returns `429` with a `retry_after_sec` field rather than queueing, so a
misbehaving client fails fast and visibly. `submit_task` additionally refuses when
`queue_depth()['todo'] >= V2_QUEUE_DEPTH_LIMIT` (`503` + current depth) — the backpressure that
stops a runaway loop from inserting 100 000 rows.

#### 3.5.5 Docker-aware endpoints

`GET /container/info` returns the container id, image tag, compose project, volume mount status,
and resolved reachability of `host.docker.internal:8787` and `:11434` — so diagnosing "why is
nothing running" takes one request instead of an exec session. Every subprocess call the server
makes carries an explicit timeout (default 120 s); there is no unbounded `subprocess.run`
anywhere in v2, which was v1's hang vector.

### 3.6 Watchdog / Service Manager — `watchdog_v2.py`

#### 3.6.1 Two-layer supervision

Docker's `restart: unless-stopped` plus `HEALTHCHECK` handles process death and hard hangs. But
Docker's restart policy does **not** act on health-check failure — an `unhealthy` container is
left running. `watchdog_v2.py` runs on the host and closes that gap, and it is also the only
component positioned to notice that the whole Docker engine is down (the state observed on
2026-09-21).

```python
"""watchdog_v2.py — host-side supervisor for the v2 containers.

Runs on Windows as a Scheduled Task (at boot, highest privileges, restart on failure).
Writes every action to daemon_watchdog_events in the HOST database, where kanban_daemon's
21 RESUSCITATED events already live — so v1 and v2 supervision share one forensic timeline.
"""

CHECK_INTERVAL_SEC    = 30
UNHEALTHY_STRIKES     = 3      # 3 x 30s = 90s unhealthy before restart
RESTART_BACKOFF_SEC   = [30, 60, 120, 300, 600]   # then hold and escalate
MAX_RESTARTS_PER_HOUR = 6      # beyond this, stop: the fault is not transient

CHECKS = (
    "docker_engine_reachable",   # docker info — the 2026-09-21 failure mode
    "container_running",         # docker inspect .State.Running
    "container_health",          # docker inspect .State.Health.Status
    "healthz_http",              # GET :8790/healthz
    "heartbeat_fresh",           # kanban_workers.last_heartbeat < 120s
    "queue_progressing",         # todo>0 and zero DONE in 30min => stalled
    "gateway_reachable",         # host :8787 — alert, never restart the container
    "wal_size_sane",             # v2 WAL < 256 MB
    "disk_free",                 # > 10 GB on D:
    "vram_headroom",             # nvidia-smi: alert above 90% — the real BSOD precursor
)
```

#### 3.6.2 Event recording

```sql
INSERT INTO daemon_watchdog_events(daemon_name, event_type, pid, details)
VALUES ('v2_work_loop', ?, ?, ?);
```

`event_type` vocabulary, extending the existing `RESUSCITATED` / `ELEVATION_DISPATCHED`:
`HEARTBEAT_OK`, `HEALTHCHECK_FAIL`, `CONTAINER_DOWN`, `DOCKER_ENGINE_DOWN`, `RESTART_ISSUED`,
`RESUSCITATED`, `RESTART_BUDGET_EXHAUSTED`, `QUEUE_STALLED`, `GATEWAY_UNREACHABLE`, `WAL_BLOAT`,
`DISK_LOW`, `VRAM_PRESSURE`, `ESCALATION_DISPATCHED`. `details` is JSON carrying the failing
check, the observed values, and the strike count.

Distinct failures get distinct responses, because restarting the wrong thing is how supervision
makes outages worse:

- `CONTAINER_DOWN` or 3× `HEALTHCHECK_FAIL` → `docker compose restart loop`, apply backoff, log
  `RESUSCITATED`.
- `DOCKER_ENGINE_DOWN` → attempt `Start-Service com.docker.service`, then escalate. Never loop.
- `GATEWAY_UNREACHABLE` → restart the **host** gateway service; do not touch the container.
- `QUEUE_STALLED` → capture `py-spy dump` of the loop's threads to
  `.logs/v2_stall_<ts>.txt` **before** restarting, so the stall stays diagnosable.
- `RESTART_BUDGET_EXHAUSTED` → stop restarting, write `ESCALATION_DISPATCHED`, drop a report at
  `D:\Gdrive\@elevation\ELEVATION_WATCHDOG_v2_work_loop_<ts>.md`, matching the existing
  elevation convention recorded in `system_metadata`.

### 3.7 LLM Execution Gateway — `llm_exec_gateway.py` (host plane)

Required by ADR-002: the container cannot execute `claude.exe` / `agy.exe`.

```python
"""llm_exec_gateway.py — host-side FastAPI wrapper around the EXISTING LLM router.

Binds 127.0.0.1:8787 only. Reachable from the container via host.docker.internal.

'Model routing preserved' is satisfied literally: this module imports and calls
llm_router.QuotaFallbackRouter without modifying it. MODEL_REGISTRY, the per-agent fallback
chains, the 429/quota detection in _is_quota_error, and the Max-subscription CLI auth all
remain exactly as they are today.
"""

import llm_router                      # UNMODIFIED — 772 lines, imported as-is
_ROUTER = llm_router.QuotaFallbackRouter()
_SEM = threading.BoundedSemaphore(int(os.environ.get("V2_GATEWAY_MAX_PARALLEL", "4")))


class GenerateRequest(BaseModel):
    agent_name: str
    prompt: str
    system: str = ""
    timeout: int = Field(default=3600, ge=10, le=7200)
    force_model: tuple[str, str] | None = None   # (provider, model) — audit asymmetry §3.4.2
    request_id: str
    task_id: str | None = None

class GenerateResponse(BaseModel):
    content: str
    provider: str            # ACTUAL provider used, after any fallback
    model: str               # ACTUAL model used, after any fallback
    elapsed_sec: float
    input_tokens: int | None
    output_tokens: int | None
    fallback_depth: int      # 0 = primary; > 0 = degraded
    pipeline_paused: bool    # llm_router.PIPELINE_PAUSED_FOR_QUOTA after the call


@app.post("/generate", response_model=GenerateResponse)
def generate(req: GenerateRequest, authorization: str = Header(None)):
    _authorize(authorization)                       # same bearer scheme as §3.5.3
    if not _SEM.acquire(timeout=5):
        raise HTTPException(429, "gateway saturated")
    try:
        llm_router.PIPELINE_PAUSED_FOR_QUOTA = False   # read back after the call
        try:
            if req.force_model:
                provider = llm_router.get_provider(req.force_model[0])
                resp = provider.generate(req.prompt, system=req.system,
                                         model=req.force_model[1],
                                         agent_name=req.agent_name, timeout=req.timeout)
            else:
                resp = _ROUTER.generate(req.agent_name, req.prompt,
                                        system=req.system, timeout=req.timeout)
        except RuntimeError as exc:
            # QuotaFallbackRouter raises "All models exhausted for agent ..." only after
            # walking the entire chain. That is the signal to pause the pipeline.
            if "All models exhausted" in str(exc):
                raise HTTPException(503, detail={"error": "quota_exhausted",
                                                 "detail": str(exc)}) from exc
            raise HTTPException(502, detail={"error": "provider_error",
                                             "detail": str(exc)[:2000]}) from exc
        return GenerateResponse(
            content=resp.content, provider=resp.provider, model=resp.model,
            elapsed_sec=resp.elapsed_sec,
            input_tokens=getattr(resp, "input_tokens", None),
            output_tokens=getattr(resp, "output_tokens", None),
            fallback_depth=_fallback_depth(req.agent_name, resp.provider, resp.model),
            pipeline_paused=llm_router.PIPELINE_PAUSED_FOR_QUOTA,
        )
    finally:
        _SEM.release()
```

Additional routes: `GET /healthz` (CLI binaries present, Ollama reachable, free semaphore
slots), `GET /router/state` (which `(provider, model)` pairs are in `_disabled` this session —
the visibility `QuotaFallbackRouter` currently lacks entirely), and `POST /router/reset` (clears
`_disabled`, which the operator needs once a quota window rolls over).

Client-side, `LLMGatewayClient` maps responses to exceptions: `503 quota_exhausted` →
`QuotaExhausted`, `429` → `GatewaySaturated` (retry with backoff), read timeout →
`GatewayTimeout`, `502` → `ProviderError`. It retries only `429` and connection errors, never
`503` — a quota exhaustion must reach the loop's pause logic rather than be retried away.

Zero downtime comes from **never running both queues over the same rows**. v1 owns
`queue_version='v1'`; v2 owns `'v2'`. Cutover redirects *new* submissions and lets v1's
in-flight work finish naturally.

**Step 1 — Freeze new v1 submissions (T+0).** Stop the MCP server that fronts v1. v1's work loop
keeps running and keeps draining.

```powershell
Stop-Process -Id 39600 -Force      # cochem_kanban_mcp.py — verify the PID first
sqlite3 d:\__CoChem\cochem_kanban.db `
  "UPDATE system_metadata SET value='draining', updated_at=datetime('now')
    WHERE key='v2_active_pipeline_version';"
```

**Step 2 — Drain v1 (T+0 → T+N).** Watch both v1 queues empty. No time limit: v1 finishes what
it started.

```powershell
do {
  $fs = (Get-ChildItem d:\__CoChem\__agentic\.scripts\prompts\*_prompt.json -EA SilentlyContinue).Count
  $db = sqlite3 d:\__CoChem\cochem_kanban.db `
        "SELECT COUNT(*) FROM kanban_tasks
          WHERE queue_version='v1' AND status IN ('in-progress','in-review');"
  "$(Get-Date -f HH:mm:ss)  fs=$fs  db_inflight=$db"
  Start-Sleep 30
} while ($fs -gt 0 -or [int]$db -gt 0)
```

**Step 3 — Stop the v1 work loop (T+N).** Only once the drain reports zero.

```powershell
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object CommandLine -like "*task_work_loop.py*" |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
# Full backup at the frozen state — this is the rollback point.
$cut = Get-Date -Format "yyyyMMdd-HHmmss"
sqlite3 d:\__CoChem\cochem_kanban.db "VACUUM INTO 'd:/__CoChem/.backups/PRECUTOVER-$cut.db'"
```

**Step 4 — Migrate residual work.** Any `queue_version='v1'` row still `todo` that belongs to an
active workflow is re-submitted into v2 with a fresh `task_id` and `parent_task_id` pointing at
the original, so lineage is preserved.

The 716 legacy `todo` rows of types `consensus_extract` / `quick_reference` / `scout_audit` are
**not** migrated. They predate this pipeline, were never executed by the v1 loop, and migrating
them would launch 716 unbudgeted LLM tasks the moment v2 came up. They stay in place as
`queue_version='v1'` for separate triage.

```powershell
python d:\__CoChem\__agentic\v2\v2_bridge.py migrate-residual `
  --host-db d:\__CoChem\cochem_kanban.db `
  --workflow-types coding,improvement,srs,syllabus,questions,presentation `
  --exclude-created-before 2026-09-01 `
  --dry-run
# Review the printed plan, then re-run without --dry-run
```

**Step 5 — Activate v2.**

```powershell
docker compose --env-file .env up -d loop mcp
docker exec cochem-v2-loop sqlite3 /data/cochem_kanban_v2.db `
  "UPDATE system_metadata SET value='v2' WHERE key='v2_active_pipeline_version';"

# Point the assistant's MCP client at v2 (edit the client's server config), then:
Start-ScheduledTask -TaskName "CoChem-V2-LLM-Gateway"
Start-ScheduledTask -TaskName "CoChem-V2-Watchdog"
```

**Step 6 — Verification checklist (all must pass, T+N → T+N+30 min).**

| # | Check | How | Expected |
|---|---|---|---|
| V1 | Containers healthy | `docker inspect --format '{{.State.Health.Status}}' cochem-v2-loop cochem-v2-mcp` | `healthy` ×2 |
| V2 | Worker registered | `SELECT status,in_flight FROM kanban_workers` | `running` |
| V3 | Gateway reachable | `curl 127.0.0.1:8787/healthz` | `200` |
| V4 | Canary submits | MCP `submit_task` ×3 (trivial coding tasks) | 3 `task_id`s |
| V5 | Canary completes | poll `get_task` | all `done` within 15 min |
| V6 | Canary audited | `SELECT verdict,asymmetry_ok FROM kanban_audit_results` | `PASS`,`1` ×3 |
| V7 | Telemetry written | `SELECT COUNT(*) FROM kanban_telemetry WHERE queue_version='v2'` | ≥ 18 (≥ 6/task) |
| V8 | Events written | `SELECT COUNT(DISTINCT event_type) FROM kanban_task_events` | ≥ 6 |
| V9 | No v1 activity | process list for `task_work_loop.py` | none |
| V10 | Watchdog beating | `SELECT * FROM daemon_watchdog_events WHERE daemon_name='v2_work_loop' ORDER BY id DESC LIMIT 5` | recent `HEARTBEAT_OK` |
| V11 | WAL bounded | `docker exec cochem-v2-loop ls -l /data/` | `*.db-wal` < 64 MB |
| V12 | Legacy untouched | `SELECT COUNT(*) FROM kanban_tasks WHERE queue_version='v1'` on the host DB | still 2525 |

If any of V1–V12 fails, execute §4.5 immediately. Do not debug forward with a half-cutover
system.

### 4.5 Rollback Plan

**Maximum tolerable downtime: 15 minutes** from decision to v1 serving again. That is
achievable because v1 is never modified or deleted during the migration — rollback means
starting two processes and pointing one config back.

State to preserve **before** rolling back:

1. The `cochem_v2_db` volume — export it, never delete it.
2. Container logs.
3. `d:\__CoChem\.backups\PRECUTOVER-<ts>.db` from Step 3 — the authoritative v1 state.
4. The list of tasks v2 accepted post-cutover, for manual replay into v1.

```powershell
# ── ROLLBACK (target: under 15 minutes) ──────────────────────────────────────
$rb = Get-Date -Format "yyyyMMdd-HHmmss"

# 1. Stop v2 accepting work. Graceful: 120s drain, in-flight tasks requeued, not lost.
docker compose -f d:\__CoChem\__agentic\v2\docker-compose.yml stop mcp
docker compose -f d:\__CoChem\__agentic\v2\docker-compose.yml stop -t 120 loop

# 2. Preserve v2 state (never delete the volume)
docker run --rm -v cochem_v2_db:/d -v d:/__CoChem/.backups:/b alpine `
  tar czf /b/v2-db-$rb.tgz -C /d .
docker compose -f d:\__CoChem\__agentic\v2\docker-compose.yml logs --no-color |
  Set-Content d:\__CoChem\.backups\v2-rollback-logs-$rb.txt

# 3. Export post-cutover v2 tasks for replay
docker exec cochem-v2-loop sqlite3 -json /data/cochem_kanban_v2.db `
  "SELECT task_id,workflow_type,prompt_text,agent_name,status,priority FROM kanban_tasks
    WHERE queue_version='v2' AND status NOT IN ('done','quarantine');" |
  Set-Content d:\__CoChem\.backups\v2-replay-$rb.json

# 4. Flip the pointer back
sqlite3 d:\__CoChem\cochem_kanban.db `
  "UPDATE system_metadata SET value='v1', updated_at=datetime('now')
    WHERE key='v2_active_pipeline_version';"

# 5. Restart v1 — unmodified, exactly as it ran before cutover
Start-Process -WindowStyle Hidden d:\__CoChem\__agentic\.venv\Scripts\python.exe `
  -ArgumentList "d:\__CoChem\__agentic\.scripts\task_work_loop.py" `
  -WorkingDirectory d:\__CoChem\__agentic
Start-Process -WindowStyle Hidden d:\__CoChem\__agentic\.venv\Scripts\python.exe `
  -ArgumentList "d:\__CoChem\__agentic\cochem_kanban_mcp.py" `
  -WorkingDirectory d:\__CoChem\__agentic
# Point the assistant's MCP client back at cochem_kanban_mcp.py

# 6. Verify v1
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object CommandLine -like "*task_work_loop.py*" | Select ProcessId, CommandLine
python d:\__CoChem\__agentic\cochem_kanban.py srs --target <a_small_known_target>
```

Rollback triggers — any one is sufficient:

- Any of V1–V12 fails and is not resolved within 10 minutes.
- Two v2 tasks reach `done` with `asymmetry_ok=0` (the audit guarantee is broken).
- `PRAGMA integrity_check` on either database returns anything but `ok`.
- The queue stalls for more than 30 minutes with `todo > 0` and the watchdog cannot recover it.
- Any evidence of a v2 write to `d:\__CoChem\cochem_kanban.db` (isolation breach).

**Rollback deletes nothing.** The `cochem_v2_db` volume, the v2 image, and the v2 source tree all
remain. The rollback window stays open for **14 days** after cutover; only then is v1 archived
(§7, final gate). Restoring the host DB from `PRECUTOVER-<ts>.db` is a separate, heavier action
reserved for actual corruption, since it discards any legitimate v1 work done after the cutover
point.
