## 5. Work Breakdown Structure (Kanban Tasks)

33 tasks. Every one is dispatched into the **v1** pipeline by
`cochem_kanban.py code --target <this document>`, which parses Appendix A. Task numbering is
strictly sequential because v1's `task_work_loop.py` orders prompt files by their numeric
`X.YZ` prefix and honours no other dependency metadata — **the number is the dependency
mechanism**. The `Depends on` field below documents the intent that the numbering already
enforces, and supplies the value to pass as `depends_on_task_id` on v2-native re-dispatch.

Every task carries `requires_audit=true`. No task reaches `done` without an asymmetric `PASS`
recorded in `kanban_audit_results` (§3.4). `Priority` is the `priority` column: 1 = critical
(blocks the migration), 2 = high (blocks a phase), 3 = normal.

Standing preamble — appended by `trigger_code()` to every prompt, and restated here so the
acceptance criteria are unambiguous: *"You must strictly adhere to the Anti-Spoofing and
Zero-Mock Protocols."* In v2 terms: write real files to disk with real content; no `pass`
bodies, no `TODO`, no `NotImplementedError`, no mocked return value standing in for logic. The
orchestrator hashes the workspace before and after the run and hands the diff to a different
model. Claiming work that was not done is detected, not suspected.
