
### Phase 3 — stress suite

Every Phase 3 task is written by `cochem-tester` rather than `cochem-coder`, and audited by
`cochem-audit`. That is deliberate: the agent that wrote a module must not also write the test
that decides whether the module works. The asymmetry rule in §3.4.2 covers execution versus
audit; this covers implementation versus verification, which is the same principle one layer
out. A test suite authored by the module's own author converges on testing what the code does
rather than what the SRS required.

All Phase 3 suites run against `/data/test_kanban_v2.db` with `V2_GATEWAY_URL` pointed at the
in-process stub from Task 3.01. No Phase 3 test may make a real LLM call — a suite that
consumes Fable-5.1 quota cannot be run fifty times while debugging a race condition, and a
suite that is too expensive to re-run stops being run.
